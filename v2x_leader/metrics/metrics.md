# V2X/NFV Simulation Metrics Reference

**Version:** 3.0
**Scope:** OMNeT++ Control Plane Metrics (Infrastructure, Service Flow, Traffic Context)

## Overview

This document describes the metrics collected during the **OMNeT++ V2X simulation**. The system is modeled as a **Network Function Virtualization (NFV)** environment where:

*   **Vehicles** are End Users.
*   **RSUs** are Edge VNFs managed by a central orchestrator.
*   **CentralRSUManager** acts as the MANO layer, handling auto-scaling and strategic propagation.

The metrics are separated into four domains: **Infrastructure (MANO)**, **Service Flows (QoS)**, **Traffic Context (Physical World)**, and **Socket Throughput**.

---

## 1. Infrastructure Metrics (`nfv_infrastructure.csv`)

**Domain:** Management & Orchestration (MANO)
**Focus:** Resource utilization, scaling behavior, and computational costs of the virtualized infrastructure.

| Column Name | Unit | Definition | NFV Significance |
| :--- | :--- | :--- | :--- |
| **SimTime** | Seconds | Current simulation timestamp. | Temporal reference. |
| **Active\_RSUs** | Count | Number of RSU VNF instances currently deployed (Static + Dynamic). | **Resource Utilization**. High numbers indicate high OpEx. |
| **Scale\_Out** | Count | Number of **new RSU instantiations** triggered by density thresholds in this interval. | **Network Expansion**. High frequency implies rapid traffic surges. |
| **Scale\_In** | Count | Number of **RSU deactivations** triggered by low density. | **Resource Reclamation**. Critical for energy efficiency. |
| **Avg\_Create\_Cost\_ms** | ms | Wall-Clock Time taken to instantiate an RSU module. | **MANO Overhead**. Computational cost of "spinning up" a VNF. |
| **Avg\_Delete\_Cost\_ms** | ms | Wall-Clock Time taken to destroy an RSU module. | **Cleanup Overhead**. |
| **Ctrl\_Overhead\_Est\_KB** | KB | Estimated bandwidth used by control signals (keep-alives, state sync). | **Control Plane Tax**. Bandwidth used for management, not user data. |

## 2. Service Flow Metrics (`service_flow.csv`)

**Domain:** Quality of Service (QoS) & Application Performance
**Focus:** End-to-end latency, service success rates, and event generation for both Safety (Accident) and URLLC (Traffic Light) services.

| Column Name | Unit | Definition | NFV Significance |
| :--- | :--- | :--- | :--- |
| **SimTime** | Seconds | Current simulation timestamp. | Temporal reference. |
| **Emergency\_Vehicles** | Count | Total number of active emergency vehicles (Ambulance/Police) in the simulation. | **Priority User Count**. |
| **Emerg\_At\_Red\_Light** | Count | Number of emergency vehicles currently stopped at a red light. | **Service Failure Indicator**. Ideally, this should be 0 if Preemption is working. |
| **Veh\_Emerg\_Sent** | Count | Total preemption requests sent by emergency vehicles. | **Service Demand**. |
| **RSU\_Emerg\_Rx** | Count | Total preemption requests received by RSUs. | **Edge Ingress Load**. |
| **Core\_Emerg\_Proc** | Count | Total requests that resulted in a successful Traffic Light phase change. | **Service Success Rate**. |
| **Avg\_TLS\_Lat\_ms** | ms | Average time from Request Sent $\to$ Phase Change. | **URLLC Latency**. The critical KPI for emergency services. |
| **Veh\_Acc\_Sent** | Count | Total unique accident reports generated by vehicles. | **Event Source**. The ground truth for safety incidents. |
| **Avg\_VehActionLatency\_ms**| ms | Average time from **Accident Occurrence** $\to$ **Vehicle Braking**. | **Safety KPI**. The total time taken for the system (Network + Logic) to react to a crash. |

## 3. Traffic Context Metrics (`traffic_context.csv`)

**Domain:** Physical Environment & Propagation Analysis
**Focus:** Correlation data explaining *how* messages reached the vehicles (V2V vs. Infrastructure) and the resulting physical behavior.

| Column Name | Unit | Definition | Significance |
| :--- | :--- | :--- | :--- |
| **SimTime** | Seconds | Current simulation timestamp. | Temporal reference. |
| **Total\_Vehicles** | Count | Total managed vehicles. | **Traffic Density**. Driver for scaling. |
| **Avg\_Net\_Speed\_mps** | m/s | Average global speed. | **Flow Quality**. Low speed = Congestion. |
| **Veh\_At\_Red\_light** | Count | Total vehicles stopped at traffic lights. | **Congestion Indicator**. |
| **Emerg\_At\_Red\_Light** | Count | (Same as Service Flow). | **Critical KPI** cross-reference. |
| **Veh\_Receiving\_V2V** | Count | Vehicles that received safety warnings via **PC5 Sidelink** (Direct Vehicle-to-Vehicle). | **Sidelink Reach**. Measures effectiveness of direct ad-hoc communication. |
| **Veh\_Receiving\_RSU** | Count | Vehicles that received safety warnings via **Local RSU Broadcast** (V2I). | **Edge Reach**. Measures coverage of the immediate RSU infrastructure. |
| **Veh\_Receiving\_Strat**| Count | Vehicles that received warnings via **Strategic Multi-Hop** (MANO-orchestrated neighbor RSUs). | **Orchestration Benefit**. Measures how many *extra* vehicles were warned due to the intelligent MANO layer. |
| **Veh\_ReactingV2V** | Count | Vehicles that braked/slowed down based on a V2V message. | **V2V Utility**. |
| **Veh\_ReactingRSU** | Count | Vehicles that braked/slowed down based on a Local RSU message. | **Edge Utility**. |
| **Veh\_Reacting\_RSUStrat**| Count| Vehicles that braked/slowed down based on a Strategic Broadcast. | **MANO Utility**. Proves the value of proactive caching for distant vehicles. |

## 4. Socket Throughput Metrics

**Domain:** Control Plane Overhead & Northbound Interface (NBI) Performance
**Focus:** Bandwidth utilization, protocol efficiency, and the cost of synchronizing the "Digital Twin" state.

This section tracks the raw data volume exchanged across the TCP interface. It is crucial for analyzing the scalability of the co-simulation: **Outbound** metrics measure the cost of state replication, while **Inbound** metrics measure the cost of network-driven actuation.

### 4.1 Outbound Throughput (`socket_throughput_sent.csv`)

**Direction:** OMNeT++ (Control Plane) $\to$ ns-3 (Data Plane)
**Trigger:** End of simulation step or asynchronous event detection.

| Column Name | Unit | Definition | Significance |
| :--- | :--- | :--- | :--- |
| **SimTime** | Seconds | Current simulation timestamp. | Temporal reference. |
| **Total\_Bytes\_Sent** | Bytes | Total size of all JSON frames sent in this step. | **Bandwidth Requirement**. Measures the load OMNeT++ places on the simulation link. |
| **Mobility\_Bytes** | Bytes | Payload size for `mobility_update` (vehicle positions/speeds). | **Baseline Cost**. Scales linearly with $N_{vehicles}$. Usually the dominant factor. |
| **RSU\_Bytes** | Bytes | Payload size for `rsu_state` (RSU positions and TLS phases). | **Infrastructure Cost**. Tracks the overhead of managing static and dynamic RSUs. |
| **EmergencyReq\_Bytes**| Bytes | Payload size for Traffic Light Preemption requests initiated by vehicles. | **URLLC Uplink Load**. Volume of high-priority control signaling. |
| **Accident\_Bytes** | Bytes | Payload size for `accident_report` and `mano_decision` frames. | **Event Load**. Spikes indicate collision events and subsequent MANO orchestration. |
| **End\_Of\_Step\_Bytes**| Bytes | Size of the synchronization footer (`t_next`). | **Protocol Overhead**. The fixed cost of the lockstep mechanism. |
| **Empty\_Payload\_Bytes**| Bytes | Bytes wasted on headers for empty lists (e.g., sending `[]` when no accidents occurred). | **Inefficiency Metric**. Ideally should be low/zero. |
| **Terminate\_Bytes** | Bytes | Size of the shutdown signal. | **Lifecycle**. Marks the end of data collection. |

### 4.2 Inbound Throughput (`socket_throughput_recv.csv`)

**Direction:** ns-3 (Data Plane) $\to$ OMNeT++ (Control Plane)
**Trigger:** Network packet delivery or simulation step completion in ns-3.

| Column Name | Unit | Definition | Significance |
| :--- | :--- | :--- | :--- |
| **SimTime** | Seconds | Timestamp when data was read from the buffer. | Temporal reference. |
| **Total\_Bytes\_Received**| Bytes | Total size of JSON frames received from ns-3. | **Reactionary Load**. The volume of commands generated by the network simulator. |
| **MANOQuery\_Bytes** | Bytes | Size of `vnf_query` messages (Core VNF requesting caching logic). | **Orchestration Demand**. Indicates how often the Core Network needs MANO intelligence. |
| **SafetyCmd\_Bytes** | Bytes | Size of `safety_command` messages (Vehicle braking triggers). | **V2X Downlink Load**. Represents successful delivery of safety warnings to vehicles. |
| **TrafficPreemption\_Bytes**| Bytes | Size of commands directing RSUs to change traffic light phases. | **URLLC Downlink Load**. Critical control commands reaching the infrastructure. |
| **TimeSync\_Bytes** | Bytes | Size of `time_sync` messages. | **Heartbeat**. Confirms ns-3 has finished the step and OMNeT++ can advance. |

## 5. Key Performance Indicators (Derived)

Using the metrics above, we can derive the following critical system KPIs:

### A. Preemption Efficiency (URLLC)
$$ \text{Efficiency} = \frac{\text{Core\_Emerg\_Proc}}{\text{Veh\_Emerg\_Sent}} \times 100\% $$
*   **Goal:** > 95%. Measures how reliably the network grants green waves.

### B. MANO Value-Add (Strategic Reach)
$$ \text{Value Add} = \frac{\text{Veh\_Receiving\_Strat}}{\text{Veh\_Receiving\_Total}} \times 100\% $$
*   **Significance:** Quantifies what percentage of warned vehicles would have been **ignorant** without the MANO layer's intervention.

### C. Network Stability (Churn)
$$ \text{Churn} = \text{Scale\_Out} + \text{Scale\_In} $$
*   **Significance:** High churn indicates the hysteresis timer is too low (flapping infrastructure).

### D. Safety Reaction Composition
Compare `Veh_ReactingV2V` vs `Veh_ReactingRSU` vs `Veh_Reacting_RSUStrat`.
*   **Insight:** Determines which transmission mode (Sidelink vs. 5G Edge vs. Orchestrated 5G) contributes most to collision avoidance in different scenarios (e.g., Highway vs. Urban).
